# 03: 定义必验组合的预期行为与支持证据规则

**What to build:** 为每个已选必验组合建立预期行为、参数处理和证据规则，使团队能制定用例并区分批准目标、验证结果与对外支持声明。

**Blocked by:** 01: 确定代表性调用场景与必验组合

**Status:** ready-for-agent

- [ ] 每个组合关联需求属性、外部预期行为和证据要求；参数行为分别记录接受、拒绝、忽略或待决定，忽略不代表支持该功能。
- [ ] 分开记录需求属性与验证状态；状态至少包括未验证、已通过、未通过和外部条件阻塞，缺少证据不得标记通过。
- [ ] 支持证据记录模型、客户端版本、参数、环境、测试时间和结果；模拟上游测试不能单独证明真实 NVIDIA 或代理兼容性。
- [ ] 记录后续验证优先从现有 `/v1/models` 和 `/v1/chat/completions` HTTP 入口检查外部行为，并核对该验证入口符合运营方预期；本票不要求执行真实兼容测试。
- [ ] 以未验证工具调用、不同客户端版本、仅有模拟 SSE 证据和缺少真实额度为反例走查；将 Winner 有效输出、流中断等未裁定问题记录为下游决策。
- [ ] 取得运营方评审并追踪 SRS-F-001、005、006、017、020、021 及 TBD-03；不得误标支持。

**Source:** GitLab issue #3，定义必验组合的预期行为与支持证据规则。
