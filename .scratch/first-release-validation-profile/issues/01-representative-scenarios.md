# 01: 确定代表性调用场景与必验组合

**What to build:** 形成经运营方确认的首发调用场景和必验组合清单，让验证人员知道验证哪些模型、客户端和调用行为，以及选择原因。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 记录受控调用方、业务场景和访问方式。
- [ ] 每个组合登记 NVIDIA 模型标识及可获得的版本/区域、客户端及版本、调用方式、优先级和选择原因；未知信息注明责任人和关闭条件，不猜测。
- [ ] 按场景覆盖常规文本、非流式、SSE、模型发现与授权、OpenAI 风格错误等核心基线，不要求所有维度做笛卡尔积。
- [ ] 将工具调用、JSON/response_format、采样参数、token 上限和流式 usage 分类为必需、候选或待决定；目标选择不代表能力已验证。
- [ ] 取得运营方对目标清单的明确批准，并关联 SRS-F-001、002、016、017、020、021 及 TBD-01、TBD-02、TBD-03；不将目标确认当作测试通过，也不缩减 SRS 首发范围。

**Source:** GitLab issue #1，确定代表性调用场景与必验组合。
